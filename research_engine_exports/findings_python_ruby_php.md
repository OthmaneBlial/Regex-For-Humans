# Python, Ruby and PHP export constraints

Research date: 2026-10-10. Five searches total; primary documentation and tagged implementation sources only. No patterns executed, software installed, source files changed, or Git staging performed.

## Editions and evidence boundary

- Python: standard-library `re` in **3.14**, Unicode `str` patterns. Live documentation currently identifies 3.14.8; tagged parser evidence below is 3.14.0. Root reports locally installed 3.14.7; this report contains no runtime verification.
- Ruby: **3.4**, UTF-8 `Regexp`, with implementation links pinned to **3.4.0**. Root reports local Ruby **2.6.10**; newer documentation does not establish that older runtime's behavior.
- PHP: recommend an explicit **PHP 8.4+ / PCRE2 10.43+** profile, then inspect `PCRE_VERSION` independently. PHP is absent locally. Current PCRE2 documentation includes newer 10.45 features; do not infer their availability from the PHP version alone.

## Shared source semantics and required lowering

JavaScript Unicode mode uses code points for matching, while its API exposes UTF-16 positions. Without `m`, `$` is strict end-of-input. With `m`, assertions recognize individual line terminators. An unset backreference succeeds as empty; lookbehind evaluates backwards. Source `\d` is ASCII, `\w` is ASCII plus appropriate Unicode case-fold additions under `i`, and `\s` follows ECMAScript whitespace. These facts make copying flags and escape text insufficient. [ECMAScript matching algorithms](https://tc39.es/ecma262/multipage/text-processing.html#sec-runtime-semantics-compileassertion), [character-class escapes](https://tc39.es/ecma262/multipage/text-processing.html#sec-runtime-semantics-compilecharacterset)

Recommended common lowering, **inference requiring native tests**: emit explicit `[0-9]`, ASCII word sets when `i` is absent, the source whitespace set, and `[^\n\r\u2028\u2029]` for ordinary dot. Use each target's strict absolute anchors when `m` is absent. For `m`, explicit one-character lookbehind/lookahead assertions around the four source line terminators avoid native newline conventions, including CRLF differences. Reject unsupported nodes before rendering snippets. Keep captures, result indexing, replacement syntax and search/global/sticky behavior as separate contracts.

## Python `re`

- Named capture becomes `(?P<name>...)`; reference becomes `(?P=name)`. Names must be valid Python identifiers and unique; numbered captures coexist. Reject incompatible/duplicate names unless a documented mapping also preserves public capture names. [Python named groups](https://docs.python.org/3.14/howto/regex.html#non-capturing-and-named-groups)
- Default `\d`, `\w`, `\b` are Unicode; default `\s` uses `str.isspace()`. `re.ASCII` also narrows whitespace, so it is not a blanket fix. `re.I` adds dotted/dotless Turkish I to `[a-z]`, unlike the source's simple folding. Reject general `i` until source-defined folding is implemented and tested. [Python `re` syntax and flags](https://docs.python.org/3.14/library/re.html)
- Emit `\uHHHH` / `\UHHHHHHHH` by AST code point, not UTF-16 code unit. The tagged parser accepts a four-digit surrogate literal; an astral point needs one eight-digit escape. Surrogate-preserving subject serialization is still a separate requirement. Forward/open references are rejected by the parser. Unset references fail during matching: reject references whose group may not participate unless exact conditional lowering is implemented. [Tagged parser](https://raw.githubusercontent.com/python/cpython/v3.14.0/Lib/re/_parser.py), [tagged backreference execution](https://raw.githubusercontent.com/python/cpython/v3.14.0/Modules/_sre/sre_lib.h)
- `^`/`$`, `re.M` and ordinary dot use LF conventions; `$` also accepts a trailing LF without `m`. Use `\A` / strict `\Z` (`\z` added in 3.14), and explicit source line/dot lowering. `re.S` supplies dot-all. Lookbehind requires a single fixed width; reject variable widths and captures/references inside lookbehind until directional behavior is verified. `\p` is unsupported; nested class/set operators are reserved rather than supported. Reject general Unicode properties and native `v` strings/set operations unless expanded to verified explicit sets/alternatives. [Python syntax](https://docs.python.org/3.14/library/re.html#regular-expression-syntax)

## Ruby `Regexp`

- `(?<name>...)` and `\k<name>` exist, but introducing any named capture suppresses ordinary unnamed captures. Reject mixed named/unnamed capture patterns and numeric references mixed with names in the initial profile; blindly preserving parentheses loses captures. [Ruby named captures](https://docs.ruby-lang.org/en/3.4/Regexp.html#class-Regexp-label-Named+Captures)
- Default `\w`/`\d`/`\s` are ASCII; default boundaries use encoding-dependent Unicode rules. Explicit ASCII word-boundary assertions or audited `(?a:...)` mode are needed when `i` is absent. Still lower source whitespace explicitly. [Primary Onigmo syntax, default and ASCII options](https://raw.githubusercontent.com/k-takata/Onigmo/master/doc/RE), [Ruby 3.4.0 option parser](https://raw.githubusercontent.com/ruby/ruby/v3_4_0/regparse.c)
- Ruby `m` is dot-all and does not change `^`/`$`; these always recognize line boundaries. Map source `s` to Ruby `m`, rewrite anchors using `\A`/`\z` or explicit source multiline assertions, and lower ordinary dot. Ruby `u` selects UTF-8 encoding; Ruby `s` selects Windows-31J, so source flag letters cannot be copied. General `i` remains unverified and should be rejected initially. [Ruby modes and encodings](https://docs.ruby-lang.org/en/3.4/Regexp.html#class-Regexp-label-Modes)
- Scalar literals can use `\u{...}`. Adopt valid UTF-8 input and reject lone-surrogate literals/subjects for this profile; Ruby ordinary string escapes reject surrogate code points, while malformed-byte regex behavior is not established here. Do not silently replace them. [Ruby Unicode escapes](https://docs.ruby-lang.org/en/3.4/syntax/literals_rdoc.html#label-Strings), [tagged string parser validation](https://raw.githubusercontent.com/ruby/ruby/v3_4_0/parse.y)
- Lookbehind must be fixed-width; different fixed-width top-level alternatives are permitted. Negative lookbehind excludes capturing groups, and the tagged compiler restricts other node types. Reject captures/references inside either lookbehind initially. Unset backreferences fail, requiring the same participation restriction as Python. [Ruby tagged lookbehind compiler](https://raw.githubusercontent.com/ruby/ruby/v3_4_0/regcomp.c), [tagged reference execution](https://raw.githubusercontent.com/ruby/ruby/v3_4_0/regexec.c)
- Properties and character-class intersection exist, but their presence proves neither ECMAScript property-name/data equivalence nor `v` string semantics. Reject general properties, `\q{...}`, string properties and unverified nested set operations. A later scalar-only set lowering can reuse Ruby intersection after precedence and case-fold checks. [Ruby Unicode properties and classes](https://docs.ruby-lang.org/en/3.4/Regexp.html#class-Regexp-label-Unicode), [Onigmo character-class grammar](https://raw.githubusercontent.com/k-takata/Onigmo/master/doc/RE)

## PHP / PCRE2

- Require `/u` for code-point matching and scalar UTF-8 subjects. It does not mean JavaScript Unicode semantics; invalid UTF-8 subjects/patterns are errors. Reject lone surrogates, including escapes: normal PCRE2 UTF validation excludes U+D800–U+DFFF. Do not use disabled validation as a translation strategy. [PHP `u` modifier](https://www.php.net/manual/en/reference.pcre.pattern.modifiers.php), [PCRE2 UTF validation](https://www.pcre.org/current/doc/html/pcre2unicode.html)
- Named captures can retain `(?<name>...)`; named references use `\k<name>` and numeric references can use unambiguous `\g{n}`. Validate names against the pinned PCRE2 edition. Unset references fail by default. Reject possibly-unset references; do not assume PHP exposes `PCRE2_MATCH_UNSET_BACKREF`. Nested captures can retain an earlier repetition's value: reject quantified optional/alternative capture patterns when observable captures or later references depend on source capture clearing. [PCRE2 reference syntax](https://www.pcre.org/current/doc/html/pcre2syntax.html#SEC27), [PHP backreferences](https://www.php.net/manual/en/regexp.reference.back-references.php), [PCRE2 capture/reference semantics](https://www.pcre.org/current/doc/html/pcre2pattern.html)
- Emit `\x{...}` for scalar code points. UTF mode and UCP are separate: UCP broadens shorthands/boundaries. Explicit source sets avoid locale/UCP drift; do not enable UCP globally as a shortcut. [PCRE2 Unicode character types](https://www.pcre.org/current/doc/html/pcre2unicode.html), [PHP escape syntax](https://www.php.net/manual/en/regexp.reference.escape.php)
- Native `i/m/s` exist, but newline conventions change anchors and ordinary dot, and default `$` accepts a final newline. Use `\A`/`\z` and source-defined line/dot lowering. General `i` needs versioned Unicode/case-fold proof; PHP 8.4's `r` modifier deliberately removes ASCII/non-ASCII folds and is not a generic fix. [PHP modifiers](https://www.php.net/manual/en/reference.pcre.pattern.modifiers.php)
- Before PCRE2 10.43, each top-level lookbehind alternative is fixed-width, up to 65,535 characters. At 10.43+, finite variable width is supported with a caller-defined maximum, default 255; unlimited repetition remains unsupported. Reject unbounded/over-limit lookbehind and unverified capture/reference directionality. PHP's older assertion page is incomplete for these newer capabilities; prefer versioned PCRE2 constraints. [PCRE2 lookbehind](https://www.pcre.org/current/doc/html/pcre2pattern.html), [older PHP assertion description](https://www.php.net/manual/en/regexp.reference.assertions.php)
- `\p` supports categories/scripts and binary properties, but requires audited name/value mappings and Unicode-version agreement. Reject unverified source properties and all string-valued properties. PCRE2 10.45 adds Perl `(?[...])` scalar set operations; newer UTS#18-style classes require another engine option. Neither establishes native `v` string sets or `\q` equivalence. Reject those constructs in the initial 10.43 profile. [PHP property syntax](https://www.php.net/manual/en/regexp.reference.unicode.php), [PCRE2 extended-class grammar](https://www.pcre.org/current/doc/html/pcre2pattern.html)

## Uncertainties to carry into implementation

These are capability/rejection findings, not a certified translator. Confirm source AST normalization, Unicode database versions, capture-reset behavior, case folding, backward lookbehind captures, empty matches, and native result positions before claiming equivalence. Especially do not extrapolate Ruby 3.4 to installed 2.6.10 or current PCRE2 features to an unknown PHP deployment. A conservative first exporter can reject those unverified features with a node-specific diagnostic while translating the proven scalar subset.
