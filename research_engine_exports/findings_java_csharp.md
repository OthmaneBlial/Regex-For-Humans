# Java and C# engine export constraints

Research date: 2026-10-10. Targets: **Java SE 25 / OpenJDK jdk-25+36**, and **.NET 10 / System.Text.RegularExpressions v10.0.0**, using the ordinary backtracking engine. Java 17.0.19 is the separately reported local runtime; this research does not establish local .NET availability. Five searches; official documentation and engine sources only. No patterns or snippets were executed.

“Exact” must cover match selection, captured values and indices on arbitrary JavaScript UTF-16 strings, including supplementary characters and lone surrogates. Escaping a source string does not establish this. Recommendations below are conservative exporter requirements, not tested implementation claims.

## Shared JavaScript baseline

JavaScript Unicode matching consumes a valid surrogate pair as one character. `\d` is ASCII; `\w` is ASCII plus the applicable Unicode case-fold equivalents under `i`; `\s` is ECMAScript whitespace and line terminators. Without `m`, `$` requires the actual input end. With `m`, anchors recognize LF, CR, U+2028 and U+2029 individually. Repetition clears enclosed captures before every iteration; a backreference to an unmatched capture succeeds empty. These rules require semantic translation, not copying similarly spelled target constructs. [ECMAScript regex algorithms](https://tc39.es/ecma262/multipage/text-processing.html#sec-regexp-regular-expression-objects), [lexical whitespace and line terminators](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-line-terminators).

## Java

| Feature | Evidence and required decision |
| --- | --- |
| Capture names and numbering | `(?<name>...)` and `\k<name>` exist. Named and unnamed groups share opening-parenthesis order. Names require `[A-Za-z][A-Za-z0-9]*`; reject unsupported source names unless the export carries an explicit name mapping. Reject duplicate source names. [Pattern groups](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Pattern.html#groupname). |
| Capture lifetime | Java explicitly retains a previous nested capture when a later quantified iteration does not capture it: `(a(b)?)+` on `aba` retains group 2 as `b`. This differs from JavaScript. Reject repetitions enclosing captures unless capture-reset equivalence is proved, including result-only differences. [Pattern capture lifetime](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Pattern.html#groupname). |
| Backreferences | The implementation fails when the referenced group did not participate. Numeric references can absorb/drop digits during parsing. Reject forward/self/possibly unmatched references; emit references from resolved AST group identities, with following digits separated. [Pinned Pattern source, BackRef and ref](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/Pattern.java). |
| Unicode and UTF-16 | Predicates consume `codePointAt` plus `charCount`. Java treats unpaired surrogates as individual code points; indices remain UTF-16 offsets. Surrogate literals/ranges, optimized atoms and search-start positions still need conformance fixtures. [Pinned Pattern source, CharProperty](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/Pattern.java), [Character](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Character.html). |
| Shorthands and boundaries | Default `\d`/`\w` are ASCII, but `\s` is only ASCII whitespace. `UNICODE_CHARACTER_CLASS` broadens all three and is not JavaScript `u`. Expand whitespace explicitly. Native `\b`/`\B` need rejection or an explicit JavaScript word-set assertion: JDK25 still has combining-mark continuation rules; JDK17 additionally uses Unicode letters/digits by default. [Pattern shorthand table](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Pattern.html), [JDK25 Bound](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/Pattern.java), [JDK17.0.19 Bound](https://raw.githubusercontent.com/openjdk/jdk17u/jdk-17.0.19%2B10/src/java.base/share/classes/java/util/regex/Pattern.java). |
| Anchors and dot | Native `$` permits a final terminator; Java multiline recognizes NEL and treats CRLF together, and `^` excludes the final empty line. Non-multiline input anchors should become `\A`/`\z`. Rewrite multiline assertions around the exact JavaScript terminator set; reject if absent. Rewrite non-dotall `.` to exclude only LF/CR/U+2028/U+2029, because Java also excludes NEL. [Pattern line terminators](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Pattern.html#lt). |
| `i`, `m`, `s` | `CASE_INSENSITIVE` is ASCII; `UNICODE_CASE` uses Java upper/lower mappings. Reject `i` without verified ECMAScript folding. `DOTALL` handles `s` after atom validation; `MULTILINE` needs rewritten anchors. Java flag `u` means case folding. [Pinned Pattern source, newSlice and flags](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/Pattern.java). |
| Lookbehind | The parser requires a calculable maximum. Candidate bodies execute forward, unlike JavaScript backward evaluation. Accept only validated capture-free finite-length bodies initially; reject captures, references and bodies without a proven bound. [Pinned Pattern source, group0/Behind](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/Pattern.java). |
| Properties and `v` | Java has categories, scripts, selected binary properties and character-class intersection/subtraction. Map only an audited property allowlist: `Script_Extensions` is not the same as `Script`. Unicode tables are version-dependent (Java25: Unicode16). Neither native class algebra nor binary emoji properties implement JavaScript string properties or `\q{...}`. Reject string sets/properties unless exact string-set lowering is implemented; character-only set operations require AST translation and folding checks. [CharPredicates](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/java.base/share/classes/java/util/regex/CharPredicates.java), [Character Unicode version](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Character.html). |
| Execution limits | The public Pattern/Matcher APIs expose no match timeout. A timed wait on an ordinary worker does not prove cancellation of a running match. Do not label a Java snippet time-bounded; a hard execution budget needs external isolation or a separately validated interruptible execution design. [Pattern API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Pattern.html), [Matcher API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Matcher.html). |

## C# / .NET

| Feature | Evidence and required decision |
| --- | --- |
| Capture names and numbering | `(?<name>...)` and `\k<name>` exist; unnamed groups are numbered first, named groups last. Resolve numeric backreferences through an AST-to-target mapping and normalize returned group order. If the export promises a native object with JavaScript numbering, reject mixed named/unnamed captures until that contract is addressed. Validate names and reject duplicates. `Group.Success` distinguishes unmatched from captured empty text. [Grouping constructs](https://learn.microsoft.com/en-us/dotnet/standard/base-types/grouping-constructs-in-regular-expressions). |
| Capture lifetime and backreferences | .NET retains capture history and the last successful capture, so repeats with optional nested captures need the same rejection/proof requirement as Java. Ordinary .NET backreferences fail for unmatched groups; ECMAScript mode changes this. Reject forward/self/possibly unmatched references without deliberate lowering. [Grouping objects](https://learn.microsoft.com/en-us/dotnet/standard/base-types/grouping-constructs-in-regular-expressions#grouping-constructs-and-regular-expression-objects), [pinned interpreter Backreference](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexInterpreter.cs). |
| Unicode and lone surrogates | Interpreter atoms consume one `char` and advance one UTF-16 unit. `.` on a supplementary character is therefore not a JavaScript Unicode atom; a surrogate pair literal under quantification must be grouped as a whole. Reject dot, negated/broad classes, supplementary ranges/properties, and surrogate-sensitive literals until scalar-aware lowering exists. Merely excluding supplementary literals from the AST is insufficient: arbitrary input can contain pairs or lone surrogates. [Pinned interpreter Forwardcharnext/Set](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexInterpreter.cs), [pinned parser literal handling](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexParser.cs). |
| Shorthands and boundaries | Default `\d` is Unicode Nd, `\w` Unicode categories, and `\s` Unicode whitespace; none is a blanket JavaScript shorthand mapping. Use explicit JavaScript sets and boundary assertions. Even ECMAScript mode is not modern JavaScript Unicode mode: pinned ECMA whitespace is ASCII and its word set includes U+0130. [Character classes](https://learn.microsoft.com/en-us/dotnet/standard/base-types/character-classes-in-regular-expressions), [pinned RegexCharClass ECMA ranges](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexCharClass.cs). |
| Anchors and dot | `\A`/`\z` are strict input anchors; native `$` also accepts before final LF. Multiline `^`/`$` recognize LF, not the JavaScript four-code-point set; default dot excludes only LF. Rewrite anchors and non-dotall dot, respecting the UTF-16 atom problem. [Anchors](https://learn.microsoft.com/en-us/dotnet/standard/base-types/anchors-in-regular-expressions), [pinned parser anchors/dot](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexParser.cs). |
| `i`, `m`, `s` and ECMAScript mode | `IgnoreCase` is culture-sensitive; `CultureInvariant` avoids locale drift but does not establish ECMAScript simple-fold equivalence. Reject `i` without audited folding. `Singleline` maps the role of `s`, subject to scalar-aware dot lowering. Do not blanket-enable ECMAScript mode: it changes class/reference parsing and cannot combine with `Singleline`; it is not `u`/`v`. Current Learn pages describe .NET11 `AnyNewLine`, which is outside the pinned .NET10 target. [Regex options](https://learn.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-options). |
| Lookbehind | Positive/negative lookbehind exists with variable-length bodies and is implemented using a right-to-left body. Capture-free bodies are a plausible subset after scalar-aware translation; captures/references require conformance fixtures. `NonBacktracking` disallows every lookaround and backreference; do not silently switch engines. [Grouping lookbehind](https://learn.microsoft.com/en-us/dotnet/standard/base-types/grouping-constructs-in-regular-expressions#zero-width-positive-lookbehind-assertions), [pinned parser lookbehind](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexParser.cs), [NonBacktracking restrictions](https://learn.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-options#nonbacktracking-mode). |
| Properties and `v` | Native properties cover general categories and named blocks, not the full JavaScript binary/script/string-property vocabulary. Blocks cannot replace scripts. .NET class subtraction is `[base-[excluded]]`; it operates on characters, not JavaScript finite strings. Reject unaudited properties and all `v` strings/string properties. Character-only operations need AST lowering plus Unicode-version and scalar checks. Learn's Unicode8 statement applies to .NET Framework, not proof of .NET10 table versions. [Character properties/subtraction](https://learn.microsoft.com/en-us/dotnet/standard/base-types/character-classes-in-regular-expressions). |
| Execution limits | Use `new Regex(pattern, options, matchTimeout)` and handle `RegexMatchTimeoutException`; the default is infinite. This bounds matching checks, not compilation, arbitrary malicious patterns or an entire multi-match operation; timeout detection can overrun the nominal interval. `NonBacktracking` is a separate restricted engine, not a transparent safety option. [Regex constructor](https://learn.microsoft.com/en-us/dotnet/api/system.text.regularexpressions.regex.-ctor?view=net-10.0), [timeouts](https://learn.microsoft.com/en-us/dotnet/standard/base-types/backtracking-in-regular-expressions#specify-a-time-out-interval), [best practices](https://learn.microsoft.com/en-us/dotnet/standard/base-types/best-practices). |

## Proposed initial contract and remaining evidence

- Export from AST identities and capability checks; never substitute language-string quoting for engine conversion.
- A small candidate subset is case-sensitive positive ASCII/BMP literals/classes excluding surrogate code units, ordinary ordering/quantifiers without repeated captures, noncapturing groups, and input anchors translated to `\A`/`\z`. This remains a candidate until native-runtime differential tests establish match and result behavior.
- Explicit diagnostics should identify the rejected feature: unsupported name, capture numbering/result mapping, capture-reset behavior, possibly unmatched reference, Unicode atom, word boundary, multiline anchor, case folding, lookbehind, property, or string set.
- Run searches against the complete input. Java `matches()` adds whole-input semantics; `Matcher` regions/anchoring bounds change assertions. A raw engine object also does not implement JavaScript `g`/`y` state, empty-match advancement, or `d` result shape; reject or provide an explicit tested execution adapter. [Matcher semantics](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/regex/Matcher.html).
- Native conformance still needs paired/lone-surrogate inputs, CRLF/final-empty-line anchors, Kelvin sign/long s/Turkish casing, combining marks, named-before-unnamed captures, unmatched references, and repeated optional captures. No runtime equivalence, timeout cancellation, or property-table parity was checked in this research.
