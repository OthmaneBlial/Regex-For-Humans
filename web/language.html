GENERATES/^ABC\d{3}$/u

Matches ABC123
Rejects ABC12, ABC1234

Use line start and line end for line-based matching. Line anchors add JavaScript's m flag. Input and line anchors cannot be mixed. When both edges are present, pair start with end, or line start with line end; the error suggests these repairs at the end anchor. A single anchor can still be used alone.

Without m, start and end match only the true input edges. They reject a final line break; m makes line anchors match each line.

space matches one whitespace character; spaces matches one or more, including tabs, nonbreaking spaces and line breaks. Counts replace that default: 3 spaces is exactly three whitespace characters, and between 0 and 2 spaces permits empty input. Use 3 " " for three ordinary spaces only. Write counts before the item; spaces 3 times and not spaces are unsupported.

letter and letters are not Unicode alphabetic classes: they exclude é by default. With i, JavaScript case folding also matches equivalents such as K and ſ; the explanation reports this. Use 3 letters or a range to limit the count.

text without: a, b matches zero or more characters outside that list. Add start and end to check the whole string. Quote punctuation and spaces in lists, for example one of: "]", "-", " ". Each item must be one Unicode code point. A literal can contain multiple characters. A trailing list comma is an error; Go to error selects that comma so you can remove it.

Use straight JSON double quotes, such as "A". Single quotes, backticks and smart quotes are not string delimiters; unsupported quoted literals and list entries offer a repair hint. Quote characters remain valid matching data inside JSON strings or as individual list items.

An empty literal "" is an error. To match only empty input, put start and end on separate lines; they produce ^$.

Unicode direction controls and C1 control characters appear as visible escapes such as \u202e and \u009b in regexes and explanations. Line separators are also displayed as escapes. Matching still uses the original values. Ordinary Arabic and Hebrew letters and emoji stay unchanged.

Lone UTF-16 surrogates are literal data, escaped for copying. Matching uses Unicode code points: joining a trailing high surrogate to a leading low surrogate forms a new astral character. A repeated literal such as 2 "\udc00A\ud800" therefore does not match that string's JavaScript .repeat(2) value.

03

HOW MANY

Repeat one thing

Put a repetition modifier before one item: 3 digits generates \d{3}, and between 2 and 4 digits generates \d{2,4}. optional "-" is the same as between 0 and 1 "-". Use zero or more digit, one or more digit or at least 3 digit for repetition without an upper limit. digits, hex digits, letters and spaces mean one or more unless a modifier replaces that default. any text and text without already match sequences.

To set their length, use countable items: 3 any character or between 2 and 4 none of: a, b. Counted sequence errors suggest these replacements. any character excludes line breaks unless s is enabled; none of: excludes only the listed characters.

FormSourceCount
3 <item> (for example, 3 digits){3}Exactly three
between 2 and 4 <item>{2,4}Two, three or four; both bounds included
optional <item>{0,1}Zero or one
zero or more <item>*Zero or more, with no upper limit
one or more <item>+One or more, with no upper limit
at least 3 <item>{3,}Three or more, with no upper limit

Numeric counts must be integers from 0 to 1,000, including the minimum in at least. In a range, the upper count must be at least the lower. between 0 and 1 "-" and optional "-" allow zero or one hyphen. A multi-character literal stays together: between 2 and 4 "AB" generates (?:AB){2,4}.

Write counts with digits 0–9; leading zeros are allowed. A sign, fraction, scientific notation or localized digit produces a count error. Every modifier needs an item: use 3 digits, rather than 3 alone. at least also needs a minimum count. Incomplete modifiers report their position and offer a complete example, such as at least 3 digits or zero or more digit.

The workshop’s Entire string mode requires a complete match; Search anywhere shows the first match, including an empty one if the pattern permits it. Search positions start at 0 and count UTF-16 code units: a match after 😀 starts at 2. These modes do not change the copied regex.

Ranges try the largest count first, then backtrack if the next rule needs it. Add start and end to validate the entire string; an unanchored range can find part of a longer string.

zero or more one of: a, b generates [ab]*: listed characters can repeat, including zero times. zero or more none of: a, b generates [^ab]*: it excludes those characters. The explanations keep membership and exclusion distinct, including after reverse translation.

The translator accepts literals, edge anchors, common digit/letter/hex classes, simple character lists, greedy repetition and non-capturing groups containing literal text. It requires u; i and s become workshop options, while m becomes line start and line end. Review the resulting rules and test your examples.

Write line breaks as escapes inside a regex literal, for example /^a\nb$/u. A physical line break inside the pattern reports an escape hint. Whitespace outside the literal is ignored.

Control-letter escapes such as \cJ (newline) and \ci (tab) translate in literals, character lists and literal groups. Both ASCII letter cases are supported; controls stay visibly escaped in the rules and generated regex. Non-letter forms such as \c0 are invalid with the required u flag.

Letter ranges accept [A-Za-z] or [a-zA-Z]. Hex ranges accept all six orders of 0-9, A-F and a-f, such as [0-9a-fA-F] or [A-Fa-f0-9]. They become letter or hex digit; the generated regex uses a canonical range order with equivalent matching.

A literal hyphen can appear at either end of a simple character list, as in [._-] or [-._], including negated lists. [-] becomes "-". Generated classes escape it as \-; unsupported ranges still report an error.

Alternation, captures, lookaround, backreferences, word boundaries, lazy quantifiers and unknown ranges are rejected with a diagnostic. Translation errors leave your current rules intact. In the library, use regexToRules(regex) and pass its returned flags to compile(rules, { flags }).

Alternation errors point to the | operator and suggest translating each alternative as a separate regex. Escaped pipes such as \| and character-class pipes such as [|] stay literal matching data.

The regex pattern and translated rules each have a 16,384 UTF-16 code-unit limit; translated rules also have a 200-line limit. Escaping and separate atoms can make the rules longer than the pattern. Output-limit errors explain this and point to column 1 for the whole regex. Syntax columns count the pattern between the slash delimiters.

A fixed-width Unicode escape pair such as \uD83D\uDE00 is one emoji atom, including inside a character class or before a repetition modifier. Separate surrogate atoms stay separate; literal groups whose surrogate boundaries cannot be represented are rejected. See the full language contract for exact limits.

05

BOUNDARIES

Flags and limits

u always

Unicode regex mode is always enabled.

i and s optional

Choose ignore case or dot matches newlines in the workshop or CLI.

m from line anchors

Line anchors enable multiline behavior automatically.

Rules are limited to 16,384 UTF-16 code units, 200 lines and numeric repetition counts up to 1,000. The workshop limits example strings and runs matching in a time-limited worker. These limits do not guarantee that a copied regex is fast in another program.

A missing closing quote points to the actual line end, including trailing spaces. Raw control characters inside unfinished quotes still report their own position. Whitespace after a closed quoted value is ignored.

Groups and raw regex are not rule-language syntax; the reverse translator accepts the documented subset as input. Alternation, lookaround, backreferences and other regex engines remain unsupported. Read the full language contract ↗, or the local Markdown source ↗ when offline.
