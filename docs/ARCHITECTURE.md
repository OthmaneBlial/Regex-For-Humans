# Architecture and compatibility policy

Regex For Humans is a dependency-free JavaScript ESM compiler with a CLI and a static browser workshop. The language is deliberately finite: each nonblank rule must match a documented instruction. There is no natural-language model, arbitrary regex passthrough or server-side compilation.

## Compilation path

```text
rules (string)
  → src/parser.js: parse and validate each line
  → src/ast.js: ordered anchors, atoms, groups and alternative branches with source locations
  → src/compiler.js: escaped JavaScript regex fragments, flags and source spans
  → src/explain.js: text attached to each emitted fragment
  → index.js: compile result and optional native RegExp
```

`src/parser.js` owns the vocabulary, grammar, input limits and syntax diagnostics. A rule cannot be silently skipped. Its output has ordered nodes and an anchor mode. `src/ast.js` defines the node shapes in JSDoc so TypeScript checks the public compiler path without a build step. `src/compiler.js` escapes literals and character-list items in their different regex contexts, applies repetition to one atom, determines flags and checks the result with `new RegExp`. `src/explain.js` receives the same AST node used for emission, so each segment can be traced to an input rule. `src/diagnostics.js` defines `CompileError` and the common failure path.

`src/display.js` provides the shared display policy for direction controls, C0/C1 control characters, DEL and Unicode line separators across compiler source, quoted data, diagnostics, trace text, CLI serialization and browser feedback. The CLI applies it to data separately from its own formatting line breaks. Matching values and original source-text metadata stay unchanged.

The public `compile(source, options)` returns `{ source, flags, segments }`. `index.d.ts` types that result and the public errors for TypeScript consumers; the package test compiles a strict consumer against the installed tarball. `segments` contain source start/end offsets (JavaScript UTF-16 indices), the emitted fragment, original instruction, explanation, one-based line/column, and node details. `toRegExp(result)` accepts a complete compile result or its string source/flags metadata, including readonly cached pairs in TypeScript. Explanation segments are not required or read. It reads the source once, then the flags once if the source is a string. It validates those same values before constructing the native JavaScript regex, preserving source-before-flags error priority and native syntax errors. `regexMatchingThroughLines(source)` is the original compatibility alias and returns only the source. The CLI calls this same public compiler; it does not maintain a second parser. It reads a file or stdin and offers a copyable regex literal or JSON result. See [LANGUAGE.md](LANGUAGE.md) for exact syntax and [TESTING.md](TESTING.md) for supported-runtime evidence.

The browser imports the same `index.js` from the static build. `web/app.js` handles editor state, examples and trace rendering. `web/match-worker.js` executes example matching away from the UI thread; `web/test-runner.js` owns cancellation and the 1,200 ms timeout. The controller reuses one completed worker, while pending checks, errors, timeouts and explicit cancellation retire it. Request IDs exclude stale replies; regexes and results are recreated for each request. `scripts/build-web.js` copies the static assets, compiler, public fixtures, docs, README, changelog, security policy and license to `dist/`. `npm run build` checks links in the exact copied documentation; `scripts/serve-dist.js` is only a local development server. The browser has no account, application backend or telemetry. Its security boundary and input limits are in [SECURITY_MODEL.md](SECURITY_MODEL.md).

The internal `TestRunner.run(payload)` reports worker construction and message-send failures through rejected `WORKER_ERROR` promises. Starting a run cancels the previous one, including when the new worker cannot start; later attempts remain available. The controller assigns the request ID after copying payload fields so an extra caller-supplied `id` cannot interfere with reply routing. Example IDs inside `cases` are preserved separately.

The workshop counter uses the parser's shared source-length limit before splitting rules. Oversized input shows “Over limit” and remains editable. Source navigation splits at most the limit plus one UTF-16 code unit, retaining the first excess unit for the existing source-limit diagnostic. Valid counters and selections retain the compiler's logical-line semantics.

Compiler option validation checks a maximum of eight unique native flag letters, rejects u/v combinations before emission, then probes native support. It avoids scanning arbitrarily long option strings and preserves canonical flag ordering.

Finite v strings reuse class members: `strings` holds JSON-decoded values and emits native `\q` members, while `stringCodePoints` retains explicit code-point sequences. Reverse parsing detects adjacent separately escaped surrogates before concatenating their UTF-16 values and preserves those boundaries through the sequence rule. Unicode property nodes and members carry `propertyType`; the seven standard string properties require v and a native capability probe. Flat complemented unions reject string properties, empty/multi-point strings and multi-part sequences. Native emission owns longest-first matching, shorter-member backtracking, capture updates and cursor state; the explanation uses the same typed data. These features require no second matching path or new dependency.

## Structured groups

Nested native v sets reuse the `characterClass` atom with an optional root operation and recursive `set` members. Operands reuse existing literal, range, shorthand, property and string parsing; only whole blocks may repeat. Union, intersection and subtraction emit native class operators, with range operands bracketed where required. Groups and sets share the 64-level parsing budget. One recursive span emitter retains every nested member's exact source and closing-rule location. Shared structural helpers implement native MayContainStrings rules and describe possible empty members; neither helper replaces runtime matching or property data. The reverse reader preserves nested operators and code-point boundaries, normalizing only existing leaf classes. The CLI and workshop continue through the same compiler and isolated worker.

`either` blocks store ordered arrays of sequence nodes in the same bounded AST. Each immediate rule starts a branch; an explicit group gives a branch multiple rules. Inline start-plus-item syntax remains within one branch. The emitter adds a noncapturing wrapper and separators, preserving precedence and capture opening order; typed `alternation` trace segments expose start/branch/end edges. Reverse parsing reads disjunctions at each group scope, keeps empty branches, and emits groups for multi-rule choices. Literal runs are flushed between branches, preserving Unicode atom boundaries. Unsupported constructs still fail explicitly; translated blocks retain source/line/depth budgets and original-regex diagnostic positions.

The workshop requests capture exploration with an optional internal `captureCount`. The worker bounds it to 100 before any matching, probes `d` dynamically, and uses internal `g` only for search enumeration. Copied regex flags are unchanged. Results include up to 100 nonoverlapping matches per example; empty matches advance by a Unicode code point. Native capture values preserve absent (`null` in the protocol) versus empty and final repeated participation. The controller snapshots input text/count/mode, validates every returned value against its span, and rejects malformed counts, participation, overlap or limit fields. Without native indices it accepts values with explicitly unavailable capture spans. Native details panels create capture tables on demand and link back to the original opening rules.

The parser uses a stack for brace-delimited groups, sharing existing atom parsing and repetition validation. Capture numbering is assigned in opening order; names are validated as Unicode JavaScript identifiers and duplicates are rejected globally. Each stack frame retains its enclosing sequence and anchor position state. The source and line budgets still apply, with an additional 64-level nesting budget. The emitter traverses this bounded tree and emits a flat, ordered trace of group openings, child rules and group closings. Existing flat-rule result shapes are preserved; the new group segment variant is declared in `index.d.ts`. The explanation, CLI JSON and workshop trace share those same nodes and numbering. Matching continues inside the terminable worker.

References are resolved against the completed capture table after parsing. A reference carries its target token's location and the enclosing groups at that point; this distinguishes missing, forward and open/self targets. The language rejects forward/open references explicitly, while preserving native empty behavior for nonparticipating optional captures. Numeric references have a noncapturing emission boundary to prevent a following literal digit from extending the reference number. CLI, declarations, explanations and workshop compilation share the resolved metadata.

## Structural visualization

`src/diagram.js` parses the same readable language and validates that AST through `compileAst` before layout. Compiler segments supply exact generated-source ranges and source locations. Containers draw nested sequences, source-ordered alternative paths and bounded repetition loops; assertions keep their check separate from the consuming rail, with lookbehind arrows pointing backwards. Character-class operands stay one semantic leaf, including string sets and nested operations. Quantifiers are not expanded into repeated nodes.

The public `toSVG` result is a self-contained static image. Labels use shared explanations, XML escaping, visible control characters and escaped lone surrogates; it contains no script, external resource or foreign HTML. The workshop imports that generated XML, adds keyboard buttons to rule nodes and connects them to the existing source/trace/pattern views. Native textarea measurements highlight wrapped source rows without changing selection or scrolling on hover. SVG work happens on demand, and each source/flag change invalidates the old diagram. Export uses the static result, excluding interactive selection state. The diagram explains structure, not native engine execution or backtracking.

## Group editing

`src/edit-group.js` edits group definitions using the parser's resolved capture table and the same compiler. It validates the original document, traverses group/assertion/alternative nodes in opening order, computes retained capture numbers and patches only the selected header and affected reference tokens. Quote-aware line splitting preserves exact UTF-16 locations across supported line separators. A referenced capture cannot become noncapturing; all other proposals are parsed and compiled again before a string is returned. The source-only `editGroup` export and local workshop form share this behavior; no second grammar or matcher is introduced.

Workshop capture highlighting reuses the native ranges already validated by the worker controller. It can show empty captures and lookaround values outside the consumed match, but never guesses spans for absent captures or runtimes without native indices. Matching retains the existing worker cancellation, result validation and deadline. These additions are not in the published dev.5 package/site.

## Unicode property atoms

An explicit `unicodeProperty` atom keeps the native alias, complement polarity, repetition and original value location. The parser validates JSON quoting and ASCII alias shape; the generator probes native property support and validates actual aliases before emitting `\p{…}` or `\P{…}`. Runtime membership owns classification and Unicode edition, avoiding a bundled property table or ASCII approximation. Typed `UnicodePropertySegment` metadata carries the alias and exact source trace through explanations, CLI and the existing isolated workshop worker. Reverse escape parsing preserves aliases and complements both standalone and inside composable classes.

## Composable character-class atoms

The `characterClass` atom stores a member union of one-code-point literals, inclusive ranges, native shorthands and property escapes. Outer-class `negative` and each property's complement remain separate fields. A class consumes one native u-mode code point; no alternation expansion or negation distribution can change u/i semantics. Parsing reuses the existing JSON reader, repetition rules and property validation. Member commas are recognized only outside quoted strings, and inline nested/repeated members are rejected with positioned diagnostics.

Generation escapes literals and range endpoints in class context and probes every property through the same native capability/alias validation as standalone atoms. `CharacterClassSegment.members` retains each member's original location/text and exact generated-source fragment/offsets for future structural consumers. Reverse class parsing identifies ranges from unescaped operator positions and preserves property complements, shorthand unions, surrogate distinctions and outer negation. Existing compact shorthand/list normalizations remain intact.

## Assertions

The same bounded block parser builds `assertion` nodes with `direction`, `negative` and child nodes. They carry no repetition. The emitter wraps those children in native positive/negative lookahead or lookbehind, preserving capture opening order and exact source spans. Typed start/end `AssertionSegment` trace entries explain the zero-width condition. The first behind assertion probes native support; failure returns a positioned `UNSUPPORTED_TARGET_FEATURE` without rewriting semantics. Source-order forward/open-reference and duplicate-name policies remain unchanged inside assertions.

Reverse group parsing recognizes all four native assertion prefixes and retains their children as structural tokens under the existing budgets. Recursive dot normalization also visits assertion children. Native matching owns lookbehind direction, assertion atomicity and capture updates. The existing capture protocol validates spans against the complete input, so captures before/after the consumed match use the same worker, validation and explorer without a second matching path.

## Reverse translation

Word and non-word boundaries use a distinct zero-width `boundary` AST node and typed `BoundarySegment`, with polarity and exact locations/spans. Native `\b` / `\B` emission shares the existing source trace, CLI and worker execution path. The reverse parser recognizes them only outside character classes; `[\b]` retains its backspace meaning. Direct boundary repetition is rejected before emission. Explanations describe native word status, input edges and case folding without claiming linguistic segmentation.

Repetition retains the same discriminated kind and bounds, with optional `lazy: true` for shortest-count-first matching. The parser applies a single leading `lazy` modifier to a validated repeated item and preserves original source locations. Compilation adds JavaScript's `?` suffix in the shared quantifier emitter; explanations distinguish the count preference without simulating matching. Reverse tokens retain that preference through literal/group normalization, alternatives, empty groups and dot-all conversion.

The public `regexToRules(regex)` delegates to `src/regex-to-rules.js`. It reads a bounded subset of Unicode JavaScript `RegExp` syntax and returns `{ rules, flags }`; native d/g/i/m/s/v/y options are retained, and u remains the implicit compatibility default. Native multiline anchors become line-anchor rules. It may add `s` for an empty negative class and express ordinary dots as explicit line-terminator exclusions when both occur together. The emitted rules are checked by the existing parser. Unsupported operators fail with positioned `CompileError` diagnostics instead of returning approximate or partial rules.

Compiler options validate unique d/g/i/m/s/u/v/y letters before native capability probing, reject u/v conflicts and use canonical ordering. Unicode mode controls literal/class escaping, property validation and complement explanations. `anchorMode` can be input, line or mixed; with m, absolute input anchors emit native zero-width input-boundary assertions while line anchors retain ^/$. All fragments and member spans describe the emitted source. Workshop controls share one flag-input map for compilation, reverse import, startup-edit detection and recipe reset. Worker enumeration merges internal d/g with requested flags once and resets both matchers at each example, retaining sticky behavior and the existing termination deadline.

Native getters read the stored metadata, including for regexes from another JavaScript context. The native flags accessor receives a projection that reads those same getters rather than instance overrides. Unsupported flags, missing Unicode mode and oversized source are rejected in that order, without serializing or reconstructing the input regex. Translation leaves `lastIndex` unchanged.

The parser also owns the output size and line limits. Reverse translation preserves its limit codes but reports that the translated rules are too large, at the start of the whole regex. Other parser errors propagate unchanged. The workshop applies rules and options only after translation succeeds, so a rejected translation preserves the current editor and matching output.

The reader preserves Unicode atom boundaries, including fixed-width surrogate pairs in repetition and character classes. Separate lone-surrogate atoms remain separate rules; a group that cannot be merged into one literal becomes a block with separate child atoms. Recursive sequence/group tokens reuse the existing escape, class and quantifier readers under the 64-level depth budget. Capturing groups retain their structure and numbering; literal-only noncapturing groups retain compact normalization. Named identifiers and reference names decode Unicode escapes. Translated rule lines carry their original regex offsets internally so unsupported reference diagnostics point into the input pattern. Dot/all-character normalization visits nested children too. Translation does not execute the input regex. The workshop and CLI's `--reverse` mode use the same internal `src/regex-literal.js` reader for slash delimiters, escapes, character classes, flags and native syntax validation. It enforces a budget of 16,392 UTF-16 code units on the complete input, including outer whitespace, before trimming or constructing a native regex. Both call the public reverse API; the workshop then uses its existing compiler and isolated example worker.

CLI reverse mode reads a UTF-8 file or stdin. JSON returns the API's `{ rules, flags }`; plain output contains reusable rules and writes any required i/s compiler options to stderr. Forward-only options are rejected before reading reverse input. This CLI option is included in the npm preview; exact publication evidence is recorded in [DISTRIBUTION.md](DISTRIBUTION.md).

## Diagnostics and changes to the language

`CompileError` carries a stable machine-readable `code`, a human message and one-based `line`/`column`; columns count UTF-16 code units, matching JavaScript string indices. An optional `hint` gives recovery advice. Invalid input must fail before returning a compile result. CLI JSON rule errors use `error.toJSON()`; invalid arguments use `CLI_USAGE`, and file/runtime errors use `CLI_ERROR`. New rule errors need a distinct code, a location test and readable wording. When a line contains a prefix or comma-separated anchor, verify that the reported column points to the relevant remaining instruction.

The documentation calls the implemented grammar **language version 1**. That is a grammar label, not a claim that npm package version 1.0 exists. The first npm candidate is the development preview `0.1.0-dev`; [DISTRIBUTION.md](DISTRIBUTION.md) records its actual publication status. Stable-release human reviews remain open.

Review a proposed new phrase for overlap with existing phrases, article and repetition handling, anchor semantics, JavaScript `u` behavior and regex performance. Add positive, negative and malformed examples before implementation. Keep the parser deterministic and reject ambiguous spelling. Update the AST only if the new instruction needs a new semantic node, then update compiler output, explanation, language docs, CLI and browser fixtures as appropriate. Do not add raw regex injection or a third-party parser without a separate security and maintenance review.

Once published, preserve documented API names, CLI flags, diagnostics and existing phrase meanings within a compatible release. An additive phrase still needs tests and release notes. A change that alters a previously valid rule's meaning, removes syntax or changes the public result shape requires an explicit migration note, a version bump appropriate to the published package version and tests for both old and new behavior. Do not silently reinterpret existing rules. The release checklist in [ROADMAP.md](https://github.com/OthmaneBlial/Regex-For-Humans/blob/main/ROADMAP.md) remains the gate for publication.

## Dependency and review policy

The runtime package has no dependencies. New dependencies should solve a documented need that the platform cannot meet simply, and reviewers should inspect package scope, license, maintenance, install size and security advisories. Keep browser scripts same-origin and avoid uploading user rules or examples. Any grammar, escaping, flag or execution change needs parser/compiler tests and browser checks; changes to the UI also need keyboard and automated accessibility checks. Human usability and screen-reader validation are separate gates.
