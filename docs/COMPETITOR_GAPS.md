# Competitor gaps and priorities

Last primary-source review: 2026-10-10. This is a living implementation checklist, not a claim of competitor runtime parity. Publisher documentation verifies the capabilities below; complete runtime behavior, safety and accessibility were not audited. Detailed sources and parser decisions are in [research findings](https://github.com/OthmaneBlial/Regex-For-Humans/blob/main/research_regex/findings.md).

## Decisions to retain

- Assertions are explicit zero-width AST nodes following [ECMAScript assertion semantics](https://tc39.es/ecma262/2025/multipage/text-processing.html#sec-runtime-semantics-compileassertion) and [backward capture behavior](https://v8.dev/blog/regexp-lookbehind-assertions). Native matching owns direction, capture updates and assertion backtracking; a structure view must not pretend to be an execution trace. Capture spans may extend before or after the consuming match and still belong to the tested input. Keep target capability failures explicit and retain the existing closed-reference policy. Word boundaries now share native zero-width semantics; Unicode constructs, broader flags, structural visualization and safety analysis remain open.
- [Word-boundary semantics](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Word_boundary_assertion) depend on ASCII word status and Unicode case folding with `i`, not linguistic word segmentation. Input edges are non-word; `\B` matches empty input. Preserve backspace inside character classes and avoid substituting Unicode letter categories for native `\w` behavior.
- Preserve deterministic rules, exact diagnostics and reversible supported syntax. A diagram should share the compiler's AST rather than parse generated source a second time.
- Standalone and class-member `u` properties now preserve native aliases and complements, validate names in the target runtime and expose typed source metadata. Next Unicode work must distinguish these `u` semantics from `v` string/set features. [Unicode property documentation](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Unicode_character_class_escape) specifies case-sensitive aliases and different complement/case-folding behavior for `u` and `v`. Character classification can depend on the runtime's Unicode data; test native parity in each selected runtime rather than claiming all engines use the same Unicode edition.
- A native Node 25.9.0 probe confirms a normalization hazard covered by the current class parser: with `iu`, `\P{Lowercase_Letter}` matches `a`, while `[^\p{Lowercase_Letter}]` does not. Both reject it with `iv`. The AST keeps property complements separate from negated classes and compares them with native capture results. `RGI_Emoji` now uses native v string-property emission with a mode/capability diagnostic; aliases retain case. Finite sets use native `\q` matching rather than ordered alternatives. Reverse translation retains separate surrogate code points because installed WebKit distinguishes them from a literal emoji. Typed nested sets now emit native union/intersection/subtraction; their differential corpus compares 43 patterns, 64 flag combinations, 53 inputs and repeated cursors.
- The [ECMAScript properties-of-strings table](https://tc39.es/ecma262/multipage/text-processing.html#table-binary-unicode-properties-of-strings) and [structural MayContainStrings rules](https://tc39.es/ecma262/multipage/text-processing.html#sec-static-semantics-maycontainstrings) define string-property names and complement restrictions. The compiler records typed string members and preserves native longest-first set behavior; the shared differential corpus compares 28 patterns under 64 flag combinations, 40 inputs and repeated cursors without inferring cross-engine Unicode-edition equivalence.
- The [native character-class reference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Character_class) describes code-point ranges and union/context escaping in u mode, and distinct nested set operators and longest-string matching in v mode. Current u classes do not expand v string properties into ordered alternatives or infer v compatibility from escaping alone.
- [regexpp](https://github.com/eslint-community/regexpp) is an AST parser if broader imports warrant it. [regex-parser](https://github.com/IonicaBizau/regex-parser.js) produces `RegExp`, so it does not solve structural parsing. Both are MIT; no dependency is adopted by this research.
- [safe-regex](https://github.com/davisjam/safe-regex) acknowledges false positives/negatives. [redos-detector](https://github.com/tjenkinson/redos-detector) exposes limits and pattern downgrade. Neither replaces the workshop's worker deadline or the application's own execution policy after copying a regex.
- [RE2](https://github.com/google/re2) rejects backreferences and lookaround, so switching engines would require a different public contract.
- Native JavaScript allows some duplicate names in disjoint alternatives and empty success for unmatched backreferences. A narrower initial rule-language policy must be stated as that policy and must not misdescribe JavaScript semantics. See the [ECMAScript specification](https://tc39.es/ecma262/2026/multipage/text-processing.html#sec-backreferencematcher).

Research did not copy source or assets, run competitor test suites, or establish a security guarantee. Revisit this checklist when support changes; verify shipped behavior against local tests and browser evidence before marking a gap closed.
