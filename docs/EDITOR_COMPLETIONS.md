# Workshop rule completion

This guide describes rule completion in the **dev.12 workshop**. Suggestions use compiler-validated English rules.

The current source checkout additionally completes balanced group/assertion templates and six native Unicode set-operation templates, retaining existing repetition prefixes on groups, captures, alternatives and sets. These follow-ups await the next verified workshop release; the hosted dev.12 workshop retains class/reference completion.

Place a single cursor after a partial built-in character class or capture reference, then choose **Complete a rule** or press **Ctrl + Space** in the editor. The native suggestion list accepts arrow keys; **Enter** or **Apply suggestion** applies the selected choice. The preview below the list displays the complete selected rule, including long names on narrow screens, without editing or saving the source. **Escape** or **Close suggestions** restores focus without editing. Normal Enter and Tab keep their native textarea behavior. On systems that reserve Ctrl + Space, use the button.

For example, `between 2 and 5 di` offers `digit` and `digits`; selecting `digits` produces `between 2 and 5 digits`. A cursor in the middle of an unfinished word replaces its remaining letters too. Only the proposed phrase is changed: indentation, UTF-16 positions, line separators, surrounding rules and existing capture/reference targets are retained. Options, examples and exact expectations remain in place; applying a suggestion participates in opted-in draft recovery.

With a previously closed capture, `same as ca` offers complete references by number and, when available, by name. For example:

```text
start
capture "token" {
  "A"
}
same as ca
end
```

Selecting `same as capture "token"` produces a valid rule matching `AA`. Open or later groups are not offered. After ten closed captures, `same as capture 1` can offer `same as capture 10`; completing it does not renumber any capture or existing reference. A closed optional capture can still be absent during matching: a suggestion validates the reference, not participation on a particular input.

Class suggestions derive from the parser's frozen shorthand vocabulary, including word/digit/letter/hex/space and path-segment forms. Reference suggestions reuse the parser's reference phrase and the compiler's closed-capture metadata. Each proposed **entire document** is parsed and compiled with the current flags before it is offered. This structural validation does not run example matching or establish native runtime support. The normal isolated matcher and existing runtime diagnostics still apply. There is no separate acceptance grammar or arbitrary natural-language interpretation.

In the source follow-up, a partial standalone line also offers eight balanced templates: `group {`, `capture {`, `optional group {`, `either {`, `followed by {`, `not followed by {`, `preceded by {` and `not preceded by {`. Shared builder templates supply sample body rules and the closing brace. The **Proposed rules** preview shows the whole resulting document, including any numbered references remapped when a new capture is inserted before existing captures. Applying places the cursor at the first body rule. Existing flags, examples and exact expectations stay unchanged; adding a capture changes the capture array shape, so review expectations that assert capture values. Leading indentation, line separators and comment text are retained. Templates are offered only at the start of a logical rule line, outside quoted content and before whitespace or a comment.

With **Unicode sets v** selected, the source workshop also offers `character set union {`, `character set intersection {` and `character set subtraction {`, together with their `not` forms. For example, `character se` offers the three positive forms; `not character se` offers the three negated forms. Union starts with the single-character operands `"A"` and `"B"`. Intersection and subtraction start with the range `"A"` to `"Z"` and the vowels `"A", "E", "I", "O", "U"`. Edit those operands after application. Negation complements the whole result, including characters outside the original range; current case-folding flags still apply. See [native set semantics](LANGUAGE.md#nested-unicode-set-operations).

Existing repetition prefixes work with group, capture, alternative and set templates: `3 cap` offers `3 capture {`; `between 1 and 3 ei` offers `between 1 and 3 either {`; and `lazy at least 2 character se` offers repeated set templates in v mode. Exact counts, `optional`, `zero or more`, `one or more`, `at least N` and `between N and M` accept the existing leading `lazy` modifier. Numeric count phrases must already be complete; completion does not invent or repair count values. Rules retain the prefix's original case and spacing. Each opener appears once; `optional group {` retains its established `"A"` sample body. Repeated captures follow native final-iteration participation, including absence at zero iterations; review exact capture expectations after adding one. See [repetition semantics](LANGUAGE.md#repetition).

Balanced completion replaces its partial standalone opener in place before validating the complete proposed document. It can supply an operand to a closed intersection/subtraction that already has one other operand, or a branch to a closed alternative with one other branch. Nested templates retain surrounding captures/references, indentation, comments and logical line separators, including separators following a quoted Unicode line separator. Capture templates still convert a noncapturing prototype through the shared reference-preserving group transformation. A proposal never moves a rule past an input anchor. The preview contains the entire validated proposal; native Undo/Redo and opted-in drafts follow the normal edit path.

Quoted text, capture names, comments and selected text receive no suggestions. Input-method composition does not trigger completion. Other syntax errors, missing outer operands/branches, an unclosed surrounding block, or source/line budgets can leave the list empty: repair them first. Invalid, duplicated, reversed or over-budget counts, a bare `lazy` group, repeated assertions and repeated operands inside a set are rejected by the shared parser/compiler. Set templates are unavailable in Unicode `u` mode, and completion never changes flags to make them work. Changing the source, options or recipe clears the list; stale source, flags or cursor positions are checked again before application. Suggestions and user text are rendered with text nodes. The list uses English DSL phrases; controls and status have all four interface translations.

Published dev.12 scope is built-in character classes and complete references to earlier closed captures; subsequent source adds eight group/assertion templates, six set-operation templates and retained repetition prefixes. Completion does not infer capture names or literal/count values, complete inside quotes, or suggest Unicode property names/local flags. Use the six builder actions or edit rules by hand for those contexts. The current source also retains [native Undo/Redo for applied rule edits](EDITOR_HISTORY.md). Independent screen-reader/usability reviews and broader grammar completion remain follow-up work.
